# 真人影视（剧集 / 电影）该用什么滤镜（调查记录）

问题：现有「AI 超分」档基于 Anime4K，对真人影视观感不佳——不是没效果，而是方向不对。
本文记录原因、可选方案与在本项目里落地的具体位置；只做调查，未改实现。

## 为什么 Anime4K 不适合真人片

Anime4K 的前提是动画画面：色块平坦、边缘是细长线条、几乎没有噪点。

- **Restore 阶段会把纹理当噪声。** 它按"边缘/平坦"二分处理，真人皮肤毛孔、织物纹理、胶片颗粒
  会被判成需要压平的部分，于是出现蜡感/塑料感；颗粒被抹掉后再放大，画面发"糊"且更"平"。
- **Upscale 阶段的收益本来就集中在边缘。** 平坦区域上它的行为接近双线性，而真人画面里平坦
  区域多、纹理多，等于花了大钱只换来边缘变硬。
- **它对压缩伪影无能为力。** 流媒体片源的主要缺陷是块效应、蚊噪、暗部色带；这些不是线条问题，
  Anime4K 的模型没见过。

## 真人片真正有效的顺序（按性价比）

1. **去色带（deband）+ 轻度去块/降噪。** 压缩伪影是片源的主要问题，先清再放。mpv 侧对应
   `--deband`（flash3kyuu）与轻度时域降噪。库内可用 `BilateralMean`（保边均值去噪），
   或 `DoG`（差分高斯提细节、对真人比 Anime4K 的 CNN 修复中性）。
2. **高质量多抽头缩放。** 1.2×–2× 放大区间，EASU（FSR1 空间放大，12 抽头）这类多抽头滤波
   在真人上比单抽头/CNN 更"自然"，也便宜得多。本项目「清晰化」档已经是 EASU+CAS，
   真正做到 2× 目标后观感提升明显。
3. **收敛的锐化。** CAS 的对比自适应锐化对真人合适，但强度要低（现有默认 0.4 合理）：
   真人脸部光晕比动画明显，锐化接近"加对比度"而不是"加细节"。
4. **通用超分 CNN（可选重档）。** mpv 社区常用的 FSRCNNX、ArtCNN（动画向）、以及
   动漫/真人兼顾的轻量模型；Anime4K 库内更重的档（`GANx3L`、`CNNx2UL`）也算这一类。
   对真人更中性，但代价高、收益相对有限，适合桌面独显作为"极致"档，不适合默认开。
5. **时域方案直接排除。** 多帧超分（TAA / 光流对齐）在同步观影里不可行：每台设备缓冲与
   播放时刻不同，没有可靠的帧对应关系。

## 落到本项目

| 方案 | 组成 | 代价 | 位置 |
| --- | --- | --- | --- |
| A. 影视档（轻） | `BilateralMean`（轻度去噪）→ EASU 放大到 ≥1.5× → CAS 低强度 | 手机也能跑（WebGL2） | `util/upscale/cas.ts` 加一个前级 pass，`UPSCALE_MODES` 加 `film` |
| B. 影视档（重） | `DoG`/`BilateralMean` → `CNNx2UL` 或 `GANx3L` 放大 → CAS | 桌面独显；发热与耗电明显 | `util/upscale/anime4k.ts` 里自建链路（库已导出这些类） |
| C. 自动建议 | 按片源/用户选择切换，而不是按"档位名字"猜内容类型 | 需要一份内容类型判断（服务适配器已知道是否为动画站点？目前没有这个字段） | `stores/settings.ts` + `VideoSettings.vue` |

**已落地（v1.1.7）**：影视档就是方案 A——`clean`（保边去噪 + 去带 + 抖动）→ EASU 放大 →
0.6 倍强度 CAS，走 WebGL2，参数、精度与降档阶梯见
[画质增强](video-enhancement.zh-CN.md#影视档的管线)。方案 B（WebGPU 重档：`DoG` / `CNNx2UL`）
仍待评估，等轻档的真机对比结论再决定。

## 验证方式

- 观测：同一片段（含暗部色带、皮肤特写、快速运动）对比 Anime4K 质量档 / 影视轻档 / 影视重档；
  看色带是否减少、皮肤是否保留纹理、脸部有无光晕。
- 数据：详情面板已有 render-target 与 render-fps；可再加一个"锐化强度实际生效值"。
- 回归：`upscale-layer.component.spec.ts` 的档位与降档用例需要跟着扩展。
