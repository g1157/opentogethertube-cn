# 手机端黑屏诊断：弹幕画布的低延迟上下文（2026-10-03）

用户在真机上报告：**手机端 Chrome（及其他 Chromium 系手机浏览器）播放时画面全黑**，有声音、进度条照走；
同一台手机直接打开视频链接、电脑浏览器打开同一房间都正常；VIA（WebView 内核）正常；画质增强未开。
唯一能露出画面的是「视频详情」面板，且露出的画面比例不对、被裁切。

## 一、现场表现（真机）

| 条件 | 结果 |
| --- | --- |
| 手机 Chrome，房间内播放 | 画面全黑（有声音、进度条在走） |
| 同机直接打开同一 mp4 链接 | 正常 |
| 桌面浏览器打开同一房间 | 正常 |
| 手机 VIA（WebView） | 正常 |
| 关掉「弹幕」开关 | 仍黑（画布元素与它的合成表面还在） |
| 打开「视频详情」面板 | 有画面（比例不对、被裁切），关掉又黑 |
| 切桌面版网站 / 横屏全屏 | 仍黑 |

## 二、真机二分（诊断页注入 CSS 变体）

在线上加了一个临时诊断页（同源、注入脚本，测完已撤），逐个切换 CSS 变体并收起面板观察：

| 变体 | 结果 |
| --- | --- |
| E1 `.danmaku-canvas { display: none }` | **出画面**（弹幕自然也看不到） |
| E6 `.player-container { backdrop-filter: blur(0.5px) }` | **画面与弹幕都正常** |
| E2/E3/E4/E5/E7/E8（视频 TZ/圆角/滤镜、去容器裁剪、隐手势层、will-change） | 仍黑 |
| 面板本身（任意变体甚至 V0 无修改） | 有面板就正常 —— 说明问题在合成层树，而不是某条具体样式 |

## 三、结论

-   **源头是弹幕画布**（E1），而**让容器进入独立渲染面即可绕开**（E6，以及「视频详情」面板自带的
    `backdrop-filter`）——这正是「打开详情就有画面、关掉就黑」的原因。
-   机制：`client/.../DanmakuLayer.vue` 里 `getContext("2d", { desynchronized: true })`（低延迟上下文，
    v1.3.2 引入）。Chromium 在部分安卓 GPU 上会把这种带 alpha 的低延迟画布**整块合成为不透明纯黑**
    （[Chromium issue 450752884](https://issues.chromium.org/issues/450752884)：`{alpha: true,
    desynchronized: true}` 时画布完全不渲染，设为 false 即恢复）。该画布压在视频之上，于是视频被整块盖住。
-   与全部现场表现一致：直链/桌面正常（没有这张画布）、VIA 正常（WebView 忽略该提示，回到标准合成）、
    关弹幕无效（canvas 元素与其黑表面仍在）、开详情有画面（`backdrop-filter` 强制走渲染面）。

## 四、修复

弹幕画布的 2D 上下文不再带 `desynchronized` 提示，回到标准合成路径；单测锁定「弹幕画布不得请求低延迟
上下文」（把提示加回去时该测试会失败）。画布尺寸、绘制与调度逻辑不变。

## 五、验证范围

真机（用户手机 Chrome）已完成二分定位；修复需在部署后于同一台手机上复验（开弹幕、开画质增强各测一遍）。
桌面 Chrome/Firefox 上弹幕渲染不受影响（本地移动端视口模拟已确认 `getContextAttributes()` 回到
`{alpha: true, desynchronized: false}`，弹幕照常绘制）。
