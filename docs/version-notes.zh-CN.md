# 版本记录（简体中文分支）

各版本的改动与数据库迁移情况。发布提交对应 Git 标签 `v0.15.0-cn2` 起；更早的历史见
`archive/history` 分支与 `v0.14.1` 标签。`v1.0.0` 起跳出 cn 序列，作为本分支的正式大版本，
标签与镜像名不再带 cn 编号。

-   **v1.3.9**：外挂弹幕新增第二条来源：自托管 **danmu_api**（兼容弹弹play 规范的聚合服务），
    非 girigiri 片源也能自动匹配弹幕。
    **匹配**：设置里填「弹幕 API 地址」（形如 `https://你的站点/danmu-api/{token}`，留空即关闭）后，
    播放器会从视频地址合成查询（`.../SHIROBAKO/06.mp4` → `SHIROBAKO S01E06`）调用 `/match` 自动
    匹配；匹配不中时可在弹幕设置里手动搜索番剧与分集。匹配结果按视频地址存在本机，同一视频只匹配
    一次，失败也记住不重试；地址更换会清掉旧的失败缓存。girigiri 片源的弹幕文件缺失（404）时同样
    回落到该来源。加载沿用 `/comment?format=xml` 的 B站格式，与 girigiri 共用同一解析与渲染。
    **实测**（本地 dev + 腾讯云自托管 danmu_api）：非 girigiri 命名的样片自动匹配到「后宫甄嬛传
    (2011)·youku 第1集」，15302 条弹幕正常渲染；animeko 源对新番与罗马音标题（SHIROBAKO）匹配良好，
    老番弹幕量取决于所配来源（B站 SESSDATA / 弹弹play 账号为可选增强）。
    **弹幕设置**：新增 API 地址输入、当前视频的匹配状态与清除、手动搜索对话框（中英文案齐全）。
    客户端 892 项测试通过（新增 17 项）。无数据库迁移、无新增依赖。

-   **v1.3.8**：修复外部弹幕在 Firefox 上整集无弹幕、在 Chromium 上只显示前一半的问题。
    **弹幕**：girigiri 的 B站转存 XML 混有裸 U+0008（退格）等 XML 1.0 非法控制字符，解析器在第一个
    非法字符处中止整份文档——Firefox 直接得到 `parsererror`（一条弹幕都不渲染，Windows 端实测即
    此现象），Chromium 只保留非法字符之前的内容（白箱 EP06 实测 1403/2694 条、EP01 3170/4286 条，
    后段静默丢失）。现在解析前先剔除非法控制字符，真机浏览器实测：Firefox 157 由 0 条变为全量
    （EP06 2694、EP01 4286），Chrome 153 同样全量。新增单测锁定「非法字符之后的弹幕仍能解析」。
    无数据库迁移、无新增依赖。

-   **v1.3.7**：修复 v1.3.6 的全屏亮度/音量手势"动一下就失效"。真机（Android Chrome）实测事件序列
    显示：`pointerdown` → 一次 `pointermove` → **`pointercancel`** → 之后所有 `touchmove` 都不再产生
    pointer 事件。原因是手势层保留着 `touch-action: pan-y pinch-zoom`（窗口模式要能滚动页面），浏览器
    把纵向拖动判给了页面滚动/pull-to-refresh，于是撤销了指针序列——表现为"短暂变化一次，之后即使不
    松手也不再响应"。合成 PointerEvent 的测试绕过了这一层，所以 v1.3.6 的测试没能拦住它。
    修复：全屏时手势层改用 `touch-action: none`（全屏本来也没有可滚动的内容），并且纵向调节手势不再
    因为指针离开元素（`pointerleave`）或跑出元素矩形而被取消（横向滑动/拖动进度条仍然照旧取消）。
    新增测试：手势层断言 `pointerleave` 不会打断调节手势；Room 层断言全屏时手势层带 `level-gestures`
    类（`touch-action: none` 的挂点）。**用 CDP 真实触摸事件**验证：单次手势内下拉到下限（亮度 20%
    饱和）后折返上拉立即变亮（0.8 → 0.728 → … → 0.089，即 91%），全程无 `pointercancel`。
    无数据库迁移、无新增依赖。
-   **v1.3.6**：全屏亮度/音量手势改为**增量累加**。v1.3.4 引入的实现取一次基准值、按手指相对起点的
    位移映射数值：手指到达屏幕边缘就无法继续调节，而且拉到上下限之后再往回拉，要先把多拉的距离
    "还回来"数值才反向变化。现在手势按段上报位移、页面逐段累加并逐段夹取范围，中途停住再继续、
    反向拉回都立即生效；一次滑动覆盖满一屏高度仍正好走完整个取值范围。新增两条测试锁定行为：手势层
    断言第二次上报是相对上一次而非起点，Room 层在全屏下派发真实指针事件、断言「到下限后再上拉立刻
    变亮」。浏览器实测：左半屏上拉到 100% 后同一次手势内下拉立刻降到 24%，右半屏下拉音量 100 → 72。
    无数据库迁移、无新增依赖。
-   **v1.3.5**：修复 v1.3.4 的遮罩黑屏。v1.3.4 把模拟亮度从设置 store 挪到独立模块时，播放器遮罩
    仍在读已不存在的字段（`1 - undefined` 得到 NaN，浏览器丢弃无效的 opacity 后回退为完全不透明），
    结果是所有端画面全黑而声音正常。遮罩现在直接读亮度模块，并补上 `RoomInteraction` 断言（默认
    `opacity: 0`、跟随亮度模块）——这正是此前漏掉、导致问题上线的检查；部署后的验证流程也补上了
    「线上真实播放一段视频」这一步。同版把服务端 `permanent-rooms` 的「检查点失败」用例改为确定性
    （原实现依赖"下一次调用"的单次 mock，CI 负载下会被更早排队的后台保存消费而偶发失败）。
    无数据库迁移、无新增依赖。

-   **v1.3.3**：修复手机端（安卓 Chrome 等）播放画面全黑、只有打开「视频详情」才露出画面的问题；
    手机通知条紧凑化。
    **黑屏根因**：v1.3.2 给弹幕画布加了 `desynchronized: true`（低延迟 2D 上下文，当时作为省电配套
    写入）。Chromium 在部分安卓 GPU 上会把这种带 alpha 的低延迟画布**整块合成为不透明纯黑**
    （Chromium issue 450752884：`{alpha: true, desynchronized: true}` 时画布完全不渲染，设为 false
    即恢复）。画布压在视频之上，于是视频被整块盖住。真机二分与此完全对应：直链、桌面浏览器、VIA
    （WebView 忽略该提示）都正常；关掉弹幕无效（canvas 元素与那张黑表面仍在）；把画布 `display: none`
    或在播放器容器上加 `backdrop-filter` 都能恢复——后者把容器渲染进独立渲染面从而绕开黑表面，这也
    就是「打开视频详情（自带 backdrop-filter 的面板）就有画面、关掉又黑」的原因。修复：不再请求低延迟
    上下文，画布回到标准合成路径；单测锁定「弹幕画布不得带该提示」。诊断过程见
    [手机端黑屏诊断](mobile-black-screen-2026-10-03.zh-CN.md)。
    **通知条**：手机（≤800px）紧凑化——取消 344px 最小宽度（在 360px 屏上等于整屏宽），内边距、字号、
    进度条与「全部关闭」按钮一并收窄，单条通知从约 48px×整屏宽降到约 31px 高的小卡片，「全部关闭」
    从整行按钮变成右侧小胶囊。桌面端样式不变。
    **控制条**：手机竖屏的精简控制条直接显示弹幕开关（此前只在设置菜单里），一键开关弹幕；弹幕设置
    面板仍从设置菜单进入，桌面端布局不变。
    无数据库迁移、无新增依赖。

    透出背景；修复「音效/画面」子菜单选项行为空的问题——选项列表产出 `title` 字段而模板读取 `text`，
    档位根本没有渲染出来（回归测试已补）。
    **弹幕**：设置面板重做为高密度行式布局（开关、不透明度滑杆、字号/速度/按类型屏蔽胶囊、防碰撞），
    控制条弹幕开关旁的设置按钮与手机菜单子页共用同一面板；默认不透明度改为 30%（本地存过 80% 旧
    默认值的一次性迁移，手动选过的不动）。渲染循环由 `requestVideoFrameCallback` 改为
    `requestAnimationFrame` + 媒体时钟：前者只在视频出新帧时触发，24fps 动漫只有约 24 次/秒的重绘，
    在 60/120Hz 屏幕上明显一顿一顿（实测重绘 24.2 次/秒，与视频帧一致）；现在重绘跟随显示刷新率，
    实测与 rAF 同频（189/189，与视频帧解耦）。省电配套：时钟未前进不重绘、暂停停循环并单次重绘、
    画布 DPR 上限 3→2、上下文 `desynchronized`。
    **Safari/WebKit**：把视频音频接入 Web Audio 后，Safari 会画面与声音一起持续卡顿，且切回原档位
    也不恢复（路由不可逆，只能重建元素）。现在 WebKit 系（Safari 与全部 iOS 浏览器）直接停用音效
    调节与音量增强，在对应位置给出说明，Chrome/Firefox 不受影响；熔断放在 Web Audio 图的入口，
    任何调用方都无法绕过。
    **手机全屏**：点全屏时尝试把屏幕方向锁到横屏（Screen Orientation API），退出全屏时解锁；iOS
    没有该 API，行为不变（用户自行旋转或原生播放器接管）。桌面宽屏不做任何方向锁定。
    **画质增强**：切换「铺满」不再重建 CNN 档管线（渲染目标保持 contain 尺寸、裁剪交给 CSS），
    避免真机上的秒级重建停顿；清晰化/影视档仍即时重算画布。
-   **v1.3.1**：播放器本机体验补齐：音效均衡、画面填充与镜像、画质档位标签。全部为本机设置

    循环冻结或旧回调在新元素上重复调度。
    **工程**：服务端覆盖率排除 `tsc` 输出目录（`ts-out`）——陈旧编译产物的 sourcemap 指向已删除源

    无此问题）。
